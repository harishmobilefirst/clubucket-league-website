## Cross-Page Consistency

**Score: 6/10.** Strong underlying design system (CSS custom properties, Layout wrapper, Section/Container components, consistent loading/error/empty states). But three different "header strategies" exist:

1. **PageHeader-based** — `about.tsx`, `news.tsx`, `highlights.tsx`, `top-scorers.tsx`, `register.tsx` use `<PageHeader>` inverse banner.
2. **Custom dark bar** — `schedule.tsx` (Fixtures/Results tabs), `standing.tsx` (division filter bar) build their own headers.
3. **No header at all** — `divisions.tsx` jumps directly into content with no introductory banner or page title.

Critical mismatch: `highlights.tsx:77` renders `<NewsCard>` instead of `<HighlightCard>`, so video items lack the play button overlay on the listing page.

---

## Overall Impression

The site is functionally robust — error handling, loading states, empty states, and data fallback chains are production-grade. The design system via CSS variables is well-executed. But the page-level composition feels template-driven rather than intentionally designed for LigaD1. The ghost-card pattern is the dominant visual language, the two content listing pages (news, highlights) are copy-paste identical, the metadata is still placeholder, and the `/standing` URL typo is baked into the route. The Schedule page and Team Profile page demonstrate what the site can do when it leans into its data — they are the strongest pages.

---

## What's Working

1. **Error/Loading/Empty state coverage is exemplary.** Every data-fetching page handles all three states consistently. The site will never show a blank page or crash.

2. **Schedule page is genuinely well-designed.** The tab+filter+grouped match cards + MatchDetailDialog pattern (`schedule.tsx`, `MatchDetailDialog.tsx`) is the best page on the site — interactive, informative, and polished.

3. **Design token system via CSS custom properties.** Runtime theme injection (`__root.tsx:170-210`) with fallback defaults (`styles.css:50-94`) is production-quality architecture.

## Priority Issues

### P0 — Highlights listing uses NewsCard instead of HighlightCard
**Location:** `highlights.tsx:77`
**What:** Renders `<NewsCard>` which has no video play overlay. Highlight items with video content lose their visual distinction.
**Fix:** Replace `<NewsCard>` with `<HighlightCard>` and pass `mediaUrl`.
**Suggested command:** `$impeccable polish`

### P0 — Root template has placeholder meta tags
**Location:** `__root.tsx:81-89`
**What:** `<title>website</title>`, `author: "Lovable"`, `og:title: "website"`, `twitter:site: "@Lovable"`. Every page inherits these.
**Fix:** Update meta tags with LigaD1-specific name, description, and social handles.
**Suggested command:** `$impeccable harden`

### P1 — Glassmorphism on MobileAppPrompt
**Location:** `MobileAppPrompt.tsx:38` — `backdropFilter: "blur(8px)"`
**What:** The only glassmorphism instance on the site violates the absolute ban.
**Fix:** Replace with a solid color overlay using `color-mix(in srgb, var(--cb-surface-inverse), transparent 20%)` without blur.
**Suggested command:** `$impeccable polish`

### P1 — Ghost-card pattern is the dominant card style site-wide
**Location:** All `cb-shadow-panel` usages — `ScoreTicker.tsx:30`, `NewsCard.tsx:15`, `HighlightCard.tsx:19`, `divisions.tsx:104`, `register.tsx:62`, `teams.$teamId.tsx:153,200`
**What:** Every card on the site uses box-shadow, creating the banned ghost-card look.
**Fix:** Differentiate card types. Some should use border only, some shadow only, some neither.
**Suggested command:** `$impeccable polish`

### P1 — Route misspelled: `/standing`
**Location:** `standing.tsx:12`
**What:** URL is `/standing` instead of `/standings`. Users typing `/standings` get a 404.
**Fix:** Rename route to `standings.tsx` or `/standings`.
**Suggested command:** `$impeccable harden`

### P2 — News and Highlights listing pages are structurally identical
**Location:** `news.tsx`, `highlights.tsx`
**What:** Both use a 3-column grid with the same card component, same pagination, same layout.
**Fix:** Differentiate highlights listing (2-col grid, `HighlightCard` with play overlay, video-first layout).
**Suggested command:** `$impeccable layout`

### P2 — Top Scorers not accessible from navbar
**Location:** `Navbar.tsx:13-21`
**What:** The page exists with full data but has no nav link. Only discoverable from home or direct URL.
**Fix:** Add a nav link (gated by module if applicable).
**Suggested command:** `$impeccable layout`

### P2 — Mixed Spanish/English abbreviations in standings
**Location:** `standing.tsx:66-73` — "POST", "L", "F", "TO"
**What:** Shortened Spanish column labels ("POST" for posición, "TO" for total de goles en contra) without clear legend.
**Fix:** Use English labels or provide an always-visible legend.
**Suggested command:** `$impeccable clarify`

## Per-Page Observations

**Home (`index.tsx`):** 8+ parallel API calls create skeleton-storm on slow connections. Long page (7 sections). ScoreTicker with pause/play is good. Division cards all show same initials ("L1") from config name instead of division-specific initials (likely a bug, line 291).

**About (`about.tsx`):** Clean but generic. "Who We Are" label bypasses `cb-eyebrow` (line 73). No descriptive alt text on image. Mission/Vision/Values cards are default template content.

**Divisions (`divisions.tsx`):** No page title or header — starts abruptly. Horizontal scroll teams with hidden scrollbar reduces discoverability. Left/right scroll buttons help but aren't obvious.

**News listing (`news.tsx`):** Clean 3-col grid with PageHeader and pagination. Uses NewsCard correctly. No issues.

**News detail (`news_.$slug.tsx`):** Best-designed page. 750px max-width reading container. All structured elements in logical order. Clean.

**Highlights listing (`highlights.tsx`):** Identical to news listing but uses NewsCard (wrong). Video items get no play overlay. P0 issue.

**Highlight detail (`highlights_.$slug.tsx`):** Video iframe support (lines 80-89) works but category detection via string match (`category?.toLowerCase().includes("video")`, line 55) is fragile.

**Schedule (`schedule.tsx`):** Best page. Tabs + dual filters + grouped cards + click-to-dialog. Match cards well-proportioned. MatchDetailDialog has goal/card columns.

**Standings (`standing.tsx`):** Division tabs functional. Table uses brand primary header. Abbreviations need legend. Table not sortable. Draws not shown.

**Top Scorers (`top-scorers.tsx`):** Clean table with season/division filters. Player avatars rounded-full (inconsistent with team badges elsewhere = rounded-md).

**Register (`register.tsx`):** Well-structured form + sidebar. No inline validation — all errors in top banner. No email/phone format check.

**Team Profile (`teams.$teamId.tsx`):** Strongest page entry — brand-colored hero with breadcrumb/logo/social links. Squad grid with player cards. Coaches section visually distinguished. Empty states for no players/coaches.

**Root (`__root.tsx`):** Theme injection robust. Placeholder meta tags (P0). 404 page and error boundary well-designed.

## Provocative Questions

2. **"Powered by Clubucket" in the footer — who is the primary audience?** Fans see the platform vendor; prospects see no "build your league" messaging. Who is this site for?

3. **The site handles every error state with surgical precision, yet the meta tags say "website" and author is "Lovable".** How did operational robustness and placeholder metadata coexist in the same commit?

4. **The home page makes 8+ parallel API calls.** Is this burst of skeletons better UX than a single page-level loader, or is it technically simpler?
